## How to use this baseline

1. Each owner compares the selected registry IDs with their test plan and updates any cases changed above. The owner may point out a concrete source contradiction; do not silently ignore the shared contract.
2. Test-plan reviewers are fixed for this baseline: F reviews O1, O3, O4 and O5; A reviews O2 and O6. A reviews each scoped OpenCode execution plan. Record the **test plan version, case IDs, approver and actual time before implementation begins**. The execution plan is then approved before the first code edit, as required by D9. These are one-to-one reviews, not another six-person requirements meeting.
3. Owners implement isolated modules on branches. C makes shared-file integration edits after module contracts are stable; A reviews the integration. F verifies default collection, all prior suites and the applicable CI gates. PR review and merge happen afterward.
